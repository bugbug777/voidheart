## 網站怎麼運作的？

網站運作的概念其實很容易理解，生活上有許多的例子可以進行類比，例如：郵局收發信的、餐廳點餐收送餐的場景，都可以作為相似場景的類比。

網站本身運作的概念不難理解，基本都是環繞在請求（request）、響應（response）這兩件事情上面，就如同你在跟別人對話的同時，你會希望提問（request）的同時得到一個答覆（response），網站運作的概念也是如此。

今天使用者造訪一個網站，其最終的目的就是希望獲取需要的資訊，可能是想要瀏覽的內容，也可以是獲得一個服務，亦或是支付任何款項的金融操作。

所以網站實際上就像是一個 24 小時待命的店家，不同的網站會提供不同的服務，甚至你可以把這些網站都當成是所謂的伺服器，說白了就是 24 小時待命的電腦。

今天我想要瀏覽特定網站的時候，我會透過瀏覽器輸入網址，或者點擊連結，進一步的發送一個 request，收到這個 request 的網站伺服器，判斷如果沒有任何問題的話，就回傳 response，這個 response 就是造訪網站的使用者想要看到的內容。

當然，上面的敘述的過程非常的濃縮、簡化，這其中還需要經歷多個步驟，才能達成最終我們想要的結果，下面我會稍微仔細的一點的拆開來說明，相信你會更明白網站是如何運作的。

## 瀏覽器輸入網址後，發生了什麼事？

一般來說，使用者會透過瀏覽器輸入網址，接著會發生一連串下面要說明的事情，但是透過瀏覽器輸入網址這個發送請求的行為，不一定只能透過瀏覽器完成，也能夠是很簡單的文字終端介面或者稱為命令提示字元介面。

瀏覽網站的流程如下：

1. 打開瀏覽器，在網址列輸入網址
2. 透過 DNS 查詢網站實際的 IP，將網址轉換成 IP
3. 使用得到的 IP 發送請求
4. 網站收到請求，處理相應的流程後發送 response 回給瀏覽器
5. 依據收到的 response 內容，將資料渲染到瀏覽器上

## 什麼是 DNS？

DNS 是 Domain Name System，可以想像成網址的電話簿，比較年輕的朋友可能沒有電話簿的概念，其實就像是 Line 裡面的好友清單，你需要先加好友（註冊），才能透過好友清單找到（查詢）朋友並且進一步的聊天、對話。

那為什麼需要 DNS，我不是已經輸入網址了嗎？電腦不是直接透過網址找到網站的？這邊會有一些用語上理解的差異，我們使用的網址，由英文以及點號分隔，通常會長這樣 `https://www.google.com`，但是這是僅供人類參考，實際上電腦不太容易處理這樣的東西，所以會透過 DNS 的查詢功能，將這個網址轉換成一組數字以及點號組成的 IP，當然這也不是那麼精確，不過聽得懂就好，IP 通常長這個樣子 `8.8.8.8`。

使用這串數字，我們的請求就能夠精準的發送到網站伺服器，並且進一步的處理我們的請求，然後發送我們想要的資訊回來。

## 網站收到請求後，實際上做了什麼？

網站收到請求後，可以做的事情很多，幾乎你在網站所有用到的服務功能都會在這裡完成，這個部分我們通常也會稱為「 後端 」。

收到來自瀏覽器或者稱為客戶端（client side）的請求，多數的網站會根據請求的內容進行不同類型的處理，如果使用者單純想要瀏覽頁面的內容，網站這邊或者稱伺服端（server side）會直接回傳相關的資訊，也就是透過 resposne 一併將這些可以被瀏覽的資料回傳給客戶端。

如果今天瀏覽的是動態的網站，也就是資料會根據不同的使用者的不同請求，回傳不同的內容，比如我今天在 Instagram 登入後，你跟我看到的頁面內容會完全不同，這就是根據不同的使用者，回傳不同的內容。

網站部分的實際狀況可能會像是這樣：

1. 收到來自使用者的請求
2. 確認使用者是否是登入的狀態（假設已登入）
3. 網站的程式，根據使用者的相關資訊，搜尋相對應存放在資料庫的資料（後端與資料庫互動）
4. 後端的程式將資料庫中的原始資料撈出後，整理、過濾後回傳給使用者
5. 使用者看到漂亮的各種圖片

## 結

這篇簡單的說明網站是怎麼運作的，不過其中還是有一些細節可以再攤開來講講，比如建立請求的機制是什麼？HTTP 是什麼？IP 是什麼？收到 response 之後，瀏覽器是怎麼將資料渲染到畫面上的？如果你慢慢喜歡上這樣探索，會發現一但開始了，這就像是個坑，永遠填不滿的坑。
