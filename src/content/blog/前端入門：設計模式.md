## 什麼是設計模式？

在 AI 還不是那麼熱絡的年代，其實也就幾年前跟十幾年前，大多時候網頁是要透過人工審視，以及手動將程式碼打出來，為了讓程式碼能夠保持足夠好的可維護性，也為了提升開發的效率，慢慢的累積出來一套規則。

設計模式其實不是前端或者計算機科學領域的專利，許多領域都會有這樣的概念，歸咎原因這是「 針對某個領域反覆出現的問題，所提煉出的通用解決方案 」，也基於這樣的概念，做 UI/UX 的可能會有一套自己的 UI Design Pattern、軟體工程也有所謂的 OOP（物件導向程式設計） 的概念，談到軟體架構也會有 MVC 架構。

在各種不同領域的專家，長久下來摸索出來的一套規則，其實就是設計模式。

## 為什麼需要設計模式？

設計模式可以提供一套通用的解決方案。

當一個專案越來越龐大的時候，興許起初只有幾百行程式碼，在這種場景下，也許不使用設計模式對程式碼做維護也沒有問題，也許還會更輕鬆？

但當專案成長到幾千行，甚至幾萬行的時候，如果沒有一些方法輔助，你將會寸步難行，這也是為什麼我們需要設計模式，來輔助我們對程式碼的架構，進行一些適度的規劃，讓我們整體程式碼更易維護、閱讀。

## OOCSS

OOCSS (**O**bject-**O**riented **CSS**)，概念上跟 OOP 很像，都是找一個標的當成物件，進一步定義相關的細節，讓其可以重複使用，而 OOCSS 的核心就是把網頁元素當成一個物件。

其實關於 CSS 的設計模式還有其他許多好用的設計模式，BEM、SMACSS、Atomic CSS ⋯⋯ 等等，這邊選擇介紹 OOCSS 是因為，我們前一篇文章介紹的 CSS 框架，Bootstrap 就是使用這種設計模式去建立 CSS。

我個人私心認為，BEM 是最好讀的，如果你想要挑選一種設計模式來學習，BEM 是個不錯的選擇，不過當前的主流是 Atomic CSS，以此為基礎的框架代表就是 TailwindCSS。

繞回來 OOCSS，OOCSS 的概念就是借鏡 OOP 的思想，大幅的提高了程式碼的重複使用性，近一步降低維護的成本。

OOCSS 的兩個核心概念：

- 結構與樣式分離（ Structure and Skin ）
- 容器與內容分離（ Container and Content ）

### 結構與樣式分離

我想樣式非常容易理解，就是可以看到的那些視覺上的 property，例如：`color`、`border`、`text-shadow` ⋯⋯ 等。

相對來說比較隱晦的是結構，例如：`margin`、`padding`、`width`、`height`、`display` ⋯⋯ 等，這些 property 會決定元件彼此之間的距離感，以及影響整體頁面的結構，甚至決定元件的形狀本身。

下面是傳統 CSS 的做法，不同的 button 的樣式幾乎一模一樣。

```css
.primary-button {
  padding: 10px 20px;
  border-radius: 4px;
  display: inline-block;
  background-color: blue;
  color: white;
}

.success-button {
  padding: 10px 20px;
  border-radius: 4px;
  display: inline-block;
  background-color: green;
  color: white;
}
```

下面這個則是依據結構與樣式分離的原則，進一步拆分撰寫的 OOCSS 的做法。

```css
/* 結構 */
.btn {
  padding: 10px 20px;
  border-radius: 4px;
  display: inline-block;
}

/* 樣式 */
.btn-primary { background-color: blue; color: white; }
.btn-success { background-color: green; color: white; }
```

通過這樣的比較，可以明白這之間的優、劣，將重複的部分提取出來，並且套用 OOCSS 的原則，讓我們的 CSS 程式碼更有架構，在維護上，今天如果想要改變全域 button 的樣式，就不用一個一個去進行修改，大大的提升效率。

### 容器與內容分離

我們前面提過，OOCSS 核心概念是把網頁元素錨定成元件，這邊的內容我們可以簡化成元件，這樣會比較好理解。

我不直接定義容器的概念，我認為我的文字描述上可能會讓你誤會，我直接透過程式碼，讓你了解容器如何與內容分離的概念。

下面是 CSS 傳統的作法。

```css
/* 只有在側邊欄裡面的標題，才會長這樣 */
.sidebar .section-title {
  font-size: 18px;
  color: #333;
  border-bottom: 1px solid #ccc;
}
```

今天有一個情境是這樣的，本來只有側邊欄的標題需要這樣的樣式，但是今天你的上級或者顧客，心血來潮覺得這個樣式真好看，想要連同主要區塊（main）以及頁尾（footer）都使用相同的樣式。

這時候如果你學過 CSS，在當前這種極簡化的情境下，你可能會直接透過這樣的方式，把樣式補上。

```css
.sidebar .section-title, .main .section-title, .footer .section-title {
  font-size: 18px;
  color: #333;
  border-bottom: 1px solid #ccc;
}
```

這時候你的標題樣式，將會一直與這三個區塊強制綁定在一起，這有一個詞可以說明這樣的概念，稱作「 強耦合 」，強耦合在程式設計中並不總是好的，不過這要依據狀況而定，至少在此處我們是不希望如此的。

依照 OOCSS 的原則，我們會希望容器可以跟內容分離，所以理想狀況會如下面的程式碼所呈現的。

```css
.heading-good {
  font-size: 18px;
  color: #333;
  border-bottom: 1px solid #ccc;
}
```

```html
<aside class="sidebar">
  <h2 class="heading-good">側欄標題</h2>
</aside>

<main class="main">
  <h2 class="heading-good">主區標題</h2>
</main>
```

透過額外定義的標題樣式附加在元素上，而不是透過權重強制錨定在特定容器上，這會提供更多的靈活性，不會限定只能用在特定容器之中，蛋蛋彈淡，但是還是要依據狀況而定，如果今天你就是希望特定樣式只能在特定容器中使用，將樣式之間的關係透過權重耦合在一起，是完全沒問題的。

## OOCSS 的優缺點

OOCSS 的優點很明顯：

- CSS 檔案縮小
- 靈活性高
- 效能提升

使用 OOCSS 可以提升效能是相對來說，CSS 檔案縮小，自然在網路傳輸效能上會較好，且有效減少 `.sidebar .menu ul li a` 這種層層堆疊的樣式，在瀏覽器的渲染效能上也會大大提升，因此整體來說效能是提升的。

缺點也是非常明顯：

- HTML 會很混亂，不容易維護
- 開發者最大惡夢，命名
- 破壞了關注點分離的架構

我們在學 CSS 時，肯定會學到將 CSS 程式碼放在獨立的檔案，然後再匯入到 HTML 檔案中，這就是關注點分離的概念，現在因為 OOCSS 把大量的 CSS 樣式碎片化，這會導致 HTML 充滿了滿滿的 CSS class，這種痛苦在你使用的同時就能體會到了。

## 結

設計模式提供了一種維護程式碼的解決方案，但是在實務開發的時候，通常會遇到各種狀況，你應該明白一點，「 沒有最好的解法，只有適合的解決方案 」，如果你也能夠體悟到這點，那麼你已經可以自詡為一個 CSS Master 了。
