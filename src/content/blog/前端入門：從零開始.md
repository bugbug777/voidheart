## 什麼是前端？

什麼是前端？如果光看中文，不同的語境可能會有不一樣解釋，單就 Web 的部分來說，前端通常指稱的是「 網站前端 」，也就是網站的前台的意思，會是使用者進入網站後會接觸到的各類互動元件、內容。

相對於前端，還有網站的後端，通常會處理一些資料庫互動，以及將一些金流操作，也就是業務上的邏輯，舉例來說：會員登錄註冊、資料持久保存、金流收付費 ⋯⋯ 諸如此類。

當然這是比較近 10 年來的區分，比較早期的網站通常沒有所謂的前、後端分別，如果你有幸認識一些「 大前輩 」，也許他會很樂意跟你分享早年的一些網頁架設的「 鬼故事 」，哈哈哈。

## 從哪開始？

這也是我要撰寫這個系列的原因，雖然當前 AI 已經能夠取代幾乎絕大多數的打字工程，但是我認為理解其中的網站製作原理相當重要，這會影響你如何架構出一個穩健的網站，當然我也不懷疑未來可能這一些都不再需要了，畢竟現在 AI 的浪潮來勢洶洶，但是如果你是抱持著學學也不是壞事的心態，那麼我強烈建議你可以繼續看下去。

下面是我預計這個系列會撰寫的內容大綱：

- 導讀，前端工程師都在做什麼？網頁是怎麼運作的？
- 開發環境架構
- HTML5
- CSS3
- JavaScript
- Git & Github 版本控管的基本使用
- 套件管理 npm/yarn 的基本概念
- CSS 預處理器以及框架的使用
- 打包工具，例如： Vite
- 主流框架的介紹，Vue

我預期會教會你一些關於網頁製作的基礎語法，如果你本身有在使用 CMS 進行網站架設的話，例如：WordPress，也許文章中的一些語法，可以幫助你進一步的修改程式的部分，當然網站的觀念更是無可或缺。

學會基礎語法之後，會簡單的引入 Git 這套版控工具，讓你可以追溯程式碼的撰寫歷史，這部分也許反而會是使用 AI 時最重要的部分，AI 取代了大部分編寫代碼的工程，但是卻不一定能夠保證每次產出都是你想要的，所以可以回溯舊版本的程式這一點就相當重要。

套件管理，為什麼會需要套件？套件其實可以想像成是外掛，然後當使用的套件越來越多時，這時候就需要一個有效的工具進行管理。

此外，這些外掛基本上也是使用基礎的語言編寫好的功能，通常工程師不會花太多的時間自己重新發明輪子，也就是明明有現有的工具，你自己硬要再花時間再寫一套，雖然自己編寫的工具不一定比較差，這取決於應用時的效益，如果某些套件工具加入太多不需要的功能，這會導致套件本身的體積過於肥大，進而導致效能低下，這時候自己編寫一套工具，也許會是個不錯的辦法。

雖然開發的時候，使用作業系統內建的文字編輯器也可以進行開發，並沒有嚴格規定一定要使用程式開發編輯工具、打包工具，但是為了加快開發的效率，以及網頁上線時，一些瑣碎事情的處理，我們會需要這些工具的幫助。

這個系列的尾聲，我會帶入一些主流框架的教學，當前主流的有 React、Vue、Angular，個有愛好使用者，這邊就挑選一個我相對比較熟悉的來介紹。
